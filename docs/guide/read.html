Read documents

A reader is a program that reads documents of the open model that another program wrote. This page gives the rules for a reader. A document from another program is input that your program does not control. Read it as data, never as instructions.

Versions

The model field names the major version and the minor version: "iris/<major>.<minor>".

  • A minor version only adds: an optional field, an enum value, a verb or a new schema.
  • A minor version never removes or renames a field. It never changes the type or the meaning of a field, and it never makes a rule stricter.
  • Each other change is a new major version, for example iris/2.0.

Compare the minor version as a number, not as text: iris/1.10 is newer than iris/1.9.

Rules for a reader

Your reader knows the newest minor version of its own schemas. This guide calls that number K. Read the minor version M of each document from model.

  1. If model is not a string that matches ^iris/1\.(0|[1-9][0-9]*)$, refuse the document. This also refuses a major version other than 1.
  2. If M is K or lower, validate the document with your schemas. If the document fails, refuse it, with the first error of the schema.
  3. If M is higher than K, you can only show the document. Read the fields that you know, ignore each unknown field, and show an unknown enum value as not known.

CAUTION: Do not take an action from a document with a minor version higher than K. Refuse it with the reason "newer than the schemas". Examples of an action: apply or approve a changeset action, send mail, change a job. A newer rule can change what a valid document is, so your reader cannot check such a document.

This Python code does rule 1 and selects between rule 2 and rule 3:

import re

MODEL = re.compile(r"iris/1\.(0|[1-9][0-9]*)")


def check_model(doc, known_minor):
    """Give "ok", "show only" or "refuse" for one JSON document.

    known_minor is K: the newest minor version of the schemas of the reader.
    After "ok", validate the document with the schemas.
    """
    model = doc.get("model")
    if not isinstance(model, str):
        return "refuse"
    # fullmatch, because "$" of re.match also accepts a newline at the end.
    match = MODEL.fullmatch(model)
    if match is None:
        return "refuse"
    if int(match.group(1)) > known_minor:
        return "show only"
    return "ok"

The policy file has no model field. Its version is 0 or 1, with the same meaning. Treat a policy file with another version as an invalid file.

Failure list

The supported input is one UTF-8 JSON document, or one line of JSON Lines, with a model value of major version 1. The policy file is TOML. For each other input, refuse the one document, say why, and take no action from it.

InputResult
Text that is not UTF-8, or not JSON (or not TOML for the policy file)Refuse the document: "not a document".
A JSON object with a key two timesRefuse the document: "duplicate key". Do not select one of the two values.
NaN, Infinity or -InfinityRefuse the document.
No model value, or a value that does not match the patternRefuse the document: "not a document of version 1".
A minor version that is not higher than K, and the document fails the schemasRefuse the document, with the first error of the schema.
A minor version higher than KShow only. Take no action from it.
A policy file with a version other than 0 or 1, or with an errorTreat it as an invalid file.
Each other error while your reader reads the documentRefuse the document. Take no action from it.

The standard JSON parser of many languages keeps the last value of a duplicate key, and accepts NaN. Turn these off. In Python, give json.loads an object_pairs_hook that refuses a duplicate key, and a parse_constant that refuses each constant. The runner of the kit does this: run.py.

Read an export of Iris

The command iris export <folder> writes the data of one Iris install into a new folder. The folder has mode 0700, because it holds the mail.

PathContent
items.jsonlEach item, one item document on each line. The gone items are also in the file. The form of each line selects the schema.
messages.jsonlEach message, one on each line, with file: the path of its raw message, or null. Version 1.0 has no schema for a message.
mail/<m-id>.emlThe raw message (RFC 5322) of each message.

All files come from one read of the store, so each reference agrees: a message names only items of items.jsonl.

To check the items of an export, do these steps:

  1. Make an empty folder.
  2. Copy items.jsonl of the export into the folder.
  3. Run run.py check on the folder (see Check your documents).

Do not run the kit on the export folder. The kit has no schema for messages.jsonl, so the check fails.

CAUTION: An export holds the mail of a person. Keep it private, and delete it when you do not need it.
