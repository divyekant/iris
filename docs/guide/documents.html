The documents of the open model

This page gives each document of version 1.0: its purpose, its required fields and one valid sample. The schema of each document is the normative copy. Each schema refuses a field that it does not name.

Contents: common fields, IDs, commitment, conversation, record, feed, signal, sender, matter, changeset, policy file, job, job item, person.

Common fields of an item

An item is a document of one of the five forms. Each item has these fields. The schema is common.schema.json ($defs/item).

FieldRequiredValue
modelyes"iris/1.0"
idyesThe ID of the item, with the prefix of its form.
formyescommitment, conversation, record, feed or signal.
statusyesThe state of the item. Each form has its own values.
titleyesOne line, 1 to 200 characters.
sourcesyesThe messages of the item. One or more sources, and exactly one source with the role origin.
created, updatedyesDate-time (RFC 3339).
derivedyesWho made the item. by is rule (with rule), model (with model and prompt) or person.
confidencenoA number from 0 to 1. Not permitted when derived.by is person.
matternoThe g- ID of the matter of the item, or null.
readyno["draft"] when Iris prepared a reply draft. The engine sets it when it reads the item.
attentionnostate is shown, bundled or hidden, with the policy rule and the reason.

A source has the fields message (an m- ID), thread (a t- ID) and role (origin, update or evidence). A source with the role origin also has quote: the words of the message that support the item, 1 to 500 characters.

A party has the field kind: self (the owner of the mailbox) or sender. A party of the kind sender also has sender (a p- ID). The fields name and address are optional.

A money value is an object with value (a decimal number as a string, for example "312.77") and currency (three capital letters, for example "USD").

IDs

An ID is a prefix and a positive number with no leading zero, for example c-311. An ID is unique in one Iris install. A document holds no ID of the mail provider, so the model does not depend on Gmail.

Commitment

An ask or a promise with an owner and a date. direction is you_owe or owed_to_you. kind is task, reply, payment, invitation or decision. status is open, done, declined, deferred, cancelled or gone. The optional due has a date or a date-time at, and strict.

Required fields:

  • model
  • id
  • form
  • status
  • title
  • sources
  • created
  • updated
  • derived
  • direction
  • owner
  • counterparty
  • kind
{
  "model": "iris/1.0",
  "id": "c-311",
  "form": "commitment",
  "status": "open",
  "title": "Review contract section 4",
  "direction": "you_owe",
  "kind": "task",
  "owner": { "kind": "self" },
  "counterparty": { "kind": "sender", "sender": "p-42", "name": "Dana Whitfield", "address": "dana@contoso.example" },
  "due": { "date": "2026-11-17", "strict": false },
  "sources": [
    { "message": "m-55210", "thread": "t-8841", "role": "origin", "quote": "Could you review section 4 by Tuesday?" }
  ],
  "created": "2026-11-16T09:02:11Z",
  "updated": "2026-11-16T09:02:11Z",
  "derived": { "by": "model", "model": "example-model-1", "prompt": "understand/0.1" },
  "confidence": 0.92,
  "matter": null
}

Schema: commitment.schema.json. Text: specification 1, section 6.2.

Sender

One address on the sender axis. kind is person (a known person), service (a known service), stranger or hostile. basis names the rule that matched. decided_by is engine or person. A decision of a person always wins.

Required fields:

  • model
  • id
  • address
  • kind
  • basis
  • decided_by
{
  "model": "iris/1.0",
  "id": "p-42",
  "address": "dana@contoso.example",
  "name": "Dana Whitfield",
  "kind": "person",
  "basis": "sent-to",
  "decided_by": "engine",
  "decided_at": "2026-11-15T10:00:00Z"
}

Schema: sender.schema.json. Text: specification 1, section 6.7.

Matter

A title and the items that belong together: a trip, a contract, a hire. Iris proposes a matter, and the person confirms it. status is proposed, confirmed or declined.

Required fields:

  • model
  • id
  • title
  • status
  • items
  • counts
  • created
  • updated
  • derived
{
  "model": "iris/1.0",
  "id": "g-5",
  "title": "Office lease",
  "status": "proposed",
  "items": ["r-1300", "v-901"],
  "counts": { "commitment": 0, "conversation": 1, "record": 1 },
  "created": "2026-11-07T09:00:00Z",
  "updated": "2026-11-07T09:00:00Z",
  "derived": { "by": "model", "model": "example-model-1", "prompt": "matters/0.1" }
}

Schema: matter.schema.json.

Changeset

The proposed actions of one author on the mailbox and on the items, with the decision of each action. author.kind is person, agent, triage or local. state is draft, open, closed or withdrawn. Each action has a verb, its targets, its arguments and a decision. The Agents page tells how an agent makes a changeset.

Required fields:

  • model
  • id
  • revision
  • author
  • why
  • created
  • submitted
  • state
  • actions
{
  "model": "iris/1.0",
  "id": "cs-80",
  "revision": 1,
  "author": {
    "kind": "person"
  },
  "why": null,
  "created": "2026-11-16T10:02:11.120Z",
  "submitted": null,
  "state": "draft",
  "actions": [
    {
      "n": 1,
      "revision": 1,
      "verb": "read",
      "targets": {
        "messages": [
          "m-61002"
        ]
      },
      "resolved": {
        "messages": []
      },
      "args": {},
      "why": null,
      "flags": [],
      "hash": null,
      "decision": null
    }
  ]
}

Schema: changeset.schema.json. Text: specification 2, section 5.

Policy file

The file policy.toml tells which actions Iris applies with no review. A person writes it in TOML, so it has no model field. version is 1 (0 has the same meaning). mode is observe (Iris applies nothing) or apply (the rules decide, and each other action goes to review). The schema checks the JSON form of the TOML data.

Required fields:

  • version
  • mode
# The policy of Iris (spec 2, section 6). Iris keeps the comments in this file.
version = 1

# observe: Iris applies nothing. apply: rules decide, and the rest goes to review.
mode = "observe"

Schema: policy.schema.json. Text: specification 2, section 6.

Job

A goal with limits for an agent, its state and the events of each change of state. state is working, waiting, needs_you or done.

Required fields:

  • model
  • id
  • goal
  • created
  • updated
  • state
  • events
{
  "model": "iris/1.0",
  "id": "j-142",
  "goal": "Get the signed contract from Dana before Nov 20.",
  "created": "2026-11-16T09:00:00Z",
  "updated": "2026-11-16T09:10:00Z",
  "state": "needs_you",
  "question": "Can I accept section 4 as Dana wrote it?",
  "events": [
    {
      "at": "2026-11-16T09:00:00Z",
      "state": "working",
      "by": "person"
    },
    {
      "at": "2026-11-16T09:10:00Z",
      "state": "needs_you",
      "by": "agent",
      "question": "Can I accept section 4 as Dana wrote it?"
    }
  ]
}

Schema: job.schema.json.

Job item

The identity of one commitment or one record in the workspace of a job. It holds no text of the model and no status. sources is a list of m- IDs.

Required fields:

  • model
  • id
  • form
  • sources
{
  "model": "iris/1.0",
  "id": "c-412",
  "form": "commitment",
  "sources": ["m-50101"]
}

Schema: jobitem.schema.json. Text: specification 3, section 5.

Person

One known person in the workspace of a job. Each value comes only from the messages in the thread files of the workspace. Each date is in UTC, with three digits of milliseconds and Z.

Required fields:

  • model
  • id
  • address
  • names
  • first
  • last
  • from_them
  • from_you
  • threads
{
  "model": "iris/1.0",
  "id": "p-1",
  "address": "dana@example.com",
  "names": [
    "Dana"
  ],
  "first": "1970-01-01T00:00:01.000Z",
  "last": "1970-01-01T00:00:09.000Z",
  "from_them": 2,
  "from_you": 1,
  "threads": [
    "t-1",
    "t-3"
  ]
}

Schema: person.schema.json. Text: specification 3, section 7.
