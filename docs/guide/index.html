Iris builder guide

This guide is for a builder: a person who writes a program that makes or reads the data of Iris. Use this guide to adopt the Iris open model in your program. You do not need the Iris code.

The open model

The open model is the data format of Iris. It is a set of JSON documents: the mail items of the five forms, the sender, the matter, the changeset, the job, the job item and the person. The policy file is TOML (Tom's Obvious Minimal Language). The JSON Schema files (draft 2020-12) are the normative copy of the model.

The current version is 1.2. Each JSON document that Iris writes has the field "model": "iris/1.2". Version 1.1 adds the optional field account to each item. Version 1.2 adds signal members, the author and the additions of a matter, and the fields withdrawn_by and comments of a changeset. Each document of an older version stays valid. The licenses are open: the text of the specifications is CC BY 4.0, and the schemas and the samples are Apache-2.0.

Three types of program

TypeWhat it doesPage
ProducerWrites documents of the open model, for example from another mail program.Write documents
ReaderReads documents of the open model, for example the output of iris export.Read documents
AgentWorks on the mail of a person through the iris command, the MCP server or a job workspace.Connect an agent

Start

  1. Read the documents. Each document has its required fields and one sample.
  2. Get the schemas and the conformance kit. They are in the folder docs/spec of the Iris repository.
  3. If your program writes documents, do the steps of Write documents. Then run the conformance kit on your output.
  4. If your program reads documents, follow the rules of Read documents.

Terms

TermMeaning
ItemOne document of one of the five forms.
FormThe type of an item: commitment, conversation, record, feed or signal.
SourceOne message that an item comes from.
PartyA person or a service in an item: the owner of the mailbox (self) or a sender.
EngineThe Iris program that keeps the store and writes the documents.
ChangesetA list of proposed actions on the mailbox. A person or a policy rule approves each action.
Conformance kitA runner and test files that check the documents of a producer, with no Iris code.

The specifications

This guide gives the rules that a builder needs. The specifications give the full rules. If the guide and a schema do not agree, the schema is correct.

  • Specification 1: the mirror, the store, the five forms and the sender axis.
  • Specification 2: the changeset, the policy file, the ledger and the iris command.
  • Specification 3: the job workspace.
  • Specification 4: the versions of the open model, the rules for a producer and a reader, and the conformance kit.
